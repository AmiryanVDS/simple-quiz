# Симпл Квиз

Совместный проект для архивации, распознавания и ведения базы вопросов
[Telegram-канала @simple_quiz](https://t.me/simple_quiz).

## Что находится в проекте

- `data/source/` — исходные таблицы в JSON.
- `telegram_archive/` — манифест канала, распознанные вопросы и локальный
  медиархив.
- `scripts/` — выгрузка, OCR, дедупликация и сборка.
- `outputs/` — готовая офлайн-HTML-база и отчёты.
- `AGENTS.md` — обязательные правила для Codex и участников.
- `CONTRIBUTING.md` — процесс совместной работы через Git.

Текущий результат:

- 528 публичных публикаций;
- 541 доступный медиафайл;
- 130 распознанных карточек;
- 130 карточек с редакторским анализом механики и сложности;
- 122 новых вопроса после дедупликации;
- 170 вопросов в итоговом каталоге.
- 205 учебных карточек в командном тренажёре, включая 21 карточку по чемпионату мира FIFA 2026.
- 39 внешних русскоязычных вопросов после удаления узких вопросов о точном счёте: финалы Лиги чемпионов, группы ЧМ-2026 и оригинальный тематический раунд ЧМ-1994.

## Быстрый старт

Проверить готовый проект:

```bash
npm run verify
```

Пересобрать итоговые файлы из сохранённых данных:

```bash
npm run build
```

OCR требует:

- Tesseract;
- языковые модели `rus` и `eng`;
- Python с Pillow.

- `outputs/Simple_Quiz_Intelligence_with_Telegram_offline.html`
- `outputs/Simple_Quiz_Team_Training.html`

Целевой формат проекта — автономный HTML. Он работает без Excel и подключения

открывают локальные файлы из `telegram_archive/media/`.

## Совместная работа двух пользователей Codex

Codex-задачи не являются общей сессией редактирования. Общим слоем должен быть
Git-репозиторий:

1. Разместите репозиторий на GitHub, GitLab или другом Git-сервере.
2. Каждый участник клонирует репозиторий в свою рабочую папку Codex.
3. Для задачи создаётся отдельная ветка.
4. Codex читает `AGENTS.md`, выполняет изменение и запускает проверку.
5. Участник отправляет ветку и создаёт pull request.
6. Второй участник проверяет diff, результаты тестов и только затем объединяет
   изменения.

Тяжёлый медиархив не хранится в обычном Git. Его нужно передавать отдельно либо
подключить Git LFS/облачное хранилище, сохраняя ту же структуру путей.

## PDMB Telegram-бот и автодеплой

Код бота находится в `pdmb_bot/`. Команды:

- `/training` — открыть командный тренажёр;
- `/schedule` — получить актуальное расписание спортивных квизов;
- `/help` — справка.

Тренажёр публикуется через GitHub Pages workflow
`deploy-training-pages.yml`. Бот разворачивается workflow
`deploy-pdmb-bot.yml` и работает как сервис `pdmb-bot.service`.

Недельное расписание и опрос публикуются по понедельникам с 10:00 МСК.
Ручной запуск `deploy-pdmb-bot.yml` с `send_poll=true` создаёт опрос для ещё
не опрошенных игр текущей недели. Игру, уже включённую в предыдущий опрос,
бот не дублирует в следующем понедельничном опросе.
Категория «Спорт» на FindQuiz включает и смешанные квизы. Перед публикацией бот
оставляет только игры проверенных спортивных организаторов или с явно
спортивной темой в названии. Публичные анонсы `@simple_quiz` («Ответная игра»),
`@quizplusmsk` и `@quizpubrangers` добавляются отдельным сборщиком в
`quiz-bot`: в расписание
попадают посты с точными датой, временем и местом, повторы одной игры
объединяются. В расписании есть ссылка на исходный анонс. Правила находятся в
`pdmb_bot/sport_filter.py` и применяются к GitHub-источнику, прямому запросу и
сохранённому кэшу. Игра нового
организатора с общим названием не попадёт в рассылку, пока организатор не будет
добавлен в список проверенных.
В день игры, включая понедельник, с 10:00 МСК бот один раз напоминает о
сегодняшних квизах и даёт ссылки на уже опубликованный недельный опрос.
Нового опроса в день игры нет. Если бот запустился позже 10:00, он досылает
напоминание до 17:00, пока игра ещё не началась. Отметка в
`weekly_poll_state.json` защищает от повторной отправки после перезапуска.
Автоматических итогов и отдельных сообщений непроголосовавшим нет.
Старые опросы поддерживаются по датам в текстах вариантов; новые также
сохраняют даты событий отдельно.

Состав команды задаётся в `pdmb_bot/team_roster.json`; бот не включается
в этот список. Ответы участников продолжают сохраняться, но автоматические
сводки по ним в чат не публикуются.

Telegram ID можно явно указать в составе команды как `user_id`; иначе бот
связывает участника с ID из
всех сохранённых голосов и новых сообщений в том же чате по известному логину,
основному имени или явно указанному варианту имени. Декоративные эмодзи
и суффикс с @username при сравнении имён не учитываются. Неоднозначное
совпадение не привязывается к ID. Известные ID сохраняются в состоянии.

Для частной привязки ID без публикации в репозитории создайте
`/opt/pdmb-bot/state/private_team_ids.json`: JSON-объект, где ключ — точное имя
из `team_roster.json`, значение — положительный числовой Telegram ID. Файл
остаётся в постоянном каталоге состояния при обновлении бота. При запуске бот
проверяет неизвестные имена и повторяющиеся ID. Для автоматической загрузки
сохраните такой JSON как секрет репозитория `PDMB_TEAM_IDS_JSON` и запустите
обычный workflow «Deploy PDMB bot». Содержимое файла не выводится в журнал.

Проверка логики бота: `python -m unittest discover -s tests -p 'test_pdmb_*.py'`.
